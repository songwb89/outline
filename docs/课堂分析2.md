## 功能概述

将课堂录音/视频自动转成带角色标注的文字稿，方便后续分析学生学习情况。

## 实现步骤

### 步骤17：教学环节执行度

#### 17.1 功能描述

**做什么**：基于教学设计（教案）与课堂授课过程，对比每个“设计环节”和“执行环节”的匹配情况，输出教学环节执行度分析结果。

本功能用于回答两个问题：

1. 教学设计中的环节，在课堂中是否被实际执行到
2. 如果执行到了，执行得有多接近设计目标，即执行度是多少

系统会将教学设计总结为结构化的“设计环节”数组，再将课堂实际授课过程整理为结构化的“执行环节”数组，最后通过模型逐条比对，输出每个设计环节对应的执行结果。

**数据来源**：

1. 步骤16中教案处理流程输出的教案文本
2. 步骤2输出的 `utterances` 数组（课堂师生对话数据，含时间戳）
3. 步骤3输出的 `teaching_phases` 数组（含主环节、子环节及时间戳）

**处理流程**：

```
教案文本（步骤16输出）
    ↓
调用AI大模型总结教学设计环节
    ↓
生成设计环节数组（2~8个环节）
    ↓
步骤2输出 utterances 数组 + 步骤3输出 teaching_phases 数组
    ↓
程序按主环节聚合子环节时间，提取每个主环节对应的课堂对话
    ↓
生成执行环节数组（主环节 + 对话内容）
    ↓
调用AI大模型比对设计环节与执行环节
    ↓
输出每个设计环节的执行度、匹配执行环节、说明
```

#### 17.2 设计环节生成规则

教案文本需要先经过模型总结，抽取出教学设计中的关键环节，形成标准化数组，供后续执行度比对使用。

**输入数据**：步骤16输出的教案文本

**输出要求**：

- 设计环节数量：2~8个
- 每个环节必须包含：
  - 环节名称
  - 环节描述
- 环节名称应概括教学设计中的一个核心步骤或教学任务
- 环节描述应保留该环节的教学目标、组织方式、教学内容或活动特征，便于后续与课堂实际执行内容比对
- 若教案内容较长，允许模型进行归纳总结，但不得遗漏关键教学逻辑

**处理流程**：

```
教案文本
    ↓
调用AI大模型总结
    ↓
输出设计环节数组
```

**JSON 结构示例**：

```json
{
  "design_phases": [
    {
      "name": "导入新课",
      "description": "教师通过问题引导或情境创设激发学生兴趣，引入本节课的学习主题。"
    },
    {
      "name": "新知讲解",
      "description": "围绕核心知识点进行讲解，结合案例、板书或演示帮助学生理解课堂重点。"
    },
    {
      "name": "课堂练习与反馈",
      "description": "组织学生完成练习或互动回答，并根据课堂表现进行即时反馈与纠正。"
    },
    {
      "name": "总结与布置作业",
      "description": "对本课内容进行归纳总结，并布置课后任务或延伸练习。"
    }
  ]
}
```

#### 17.3 执行环节生成规则

课堂授课过程的数据来自步骤2和步骤3。

步骤3已经识别出主环节和子环节，因此程序先按主环节进行聚合，再把该主环节范围内的课堂对话提取出来，形成执行环节数据。

**处理方式**：

1. 读取步骤3输出的 `teaching_phases`
2. 对每个主环节，取其下所有子环节中：
   - 第一个子环节的 `start_ms` 作为主环节起始时间
   - 最后一个子环节的 `end_ms` 作为主环节结束时间
3. 使用该时间区间去筛选步骤2输出的 `utterances`
4. 获取该主环节内的课堂对话内容，形成执行环节数组

**执行环节数组结构**：

- 主环节名称
- 主环节下的课堂对话内容

说明：这里的执行环节不再细分子环节，而是以主环节为单位，保留该环节内的完整对话上下文，供后续与设计环节进行语义匹配。

**JSON 结构示例**：

```json
{
  "execution_phases": [
    {
      "name": "课堂导入",
      "transcript": [
        {
          "text": "已经在的同学打开书，背一下春江花月夜啊，自己。",
          "role": "teacher"
        },
        {
          "text": "老师，我已经打开了。",
          "role": "student"
        }
      ]
    },
    {
      "name": "新知讲解",
      "transcript": [
        {
          "text": "接下来我们来看这一句的意思。",
          "role": "teacher"
        },
        {
          "text": "这里为什么要这样理解？",
          "role": "student"
        }
      ]
    },
    {
      "name": "课堂练习",
      "transcript": [
        {
          "text": "现在请同学们独立完成第三题。",
          "role": "teacher"
        },
        {
          "text": "我写完了。",
          "role": "student"
        }
      ]
    }
  ]
}
```

#### 17.4 AI 比对规则

系统会把“设计环节数组”和“执行环节数组”同时输入模型，由模型逐条判断匹配关系。

**比对目标**：

- 一个设计环节对应课堂中最相近的一个执行环节
- 如果课堂中没有与该设计环节相匹配的执行内容，则该设计环节可判定为未执行
- 如果匹配不完整，则输出部分匹配，并给出执行度百分比

**执行度定义**：

- 执行度表示“课堂实际执行内容”与“教学设计环节”在语义与行为层面的贴合程度
- 执行度范围为 0~100
- 执行度越高，说明课堂实际开展内容越接近教案设计
- 若完全不匹配，则该设计环节对应的执行环节可为 `0`，且执行度与说明不输出

**执行度标签规则**：

- `>= 90%`：完全匹配
- `< 90%`&`>0`：部分匹配

说明：执行度标签由前端根据执行度数值映射生成，不需要模型直接返回标签。

#### 17.5 输出数据结构（AI生成）

**JSON 结构示例**：

```json
{
  "teaching_design_execution": [
    {
      "design_phase_name": "导入新课，激发兴趣",
      "execution_phase_name": "课堂导入与朗读",
      "execution_degree": 92,
      "execution_comment": "课堂导入环节与教案设计基本一致，教师通过朗读和提问完成了预设的教学目标，整体节奏和内容贴合度较高。"
    },
    {
      "design_phase_name": "分组讨论，探究核心问题",
      "execution_phase_name": "小组交流与教师追问",
      "execution_degree": 78,
      "execution_comment": "课堂中出现了相关讨论，但讨论时间和深度不足，教师更多承担了引导和补充说明的角色，因此与教案设计存在一定偏差。"
    },
    {
      "design_phase_name": "课堂总结与作业布置",
      "execution_phase_name": 0,
      "execution_degree": null,
      "execution_comment": null
    }
  ],
  "ai_analysis": {
    "comment": "本课整体围绕教学主线展开，导入与新知讲解环节执行较好，课堂节奏较为连贯，但讨论深化和总结收束环节相对不足。",
    "suggestion": "建议在后续课堂中适当增加学生讨论与表达的时间，并在结尾加强归纳总结与作业布置，提升教学闭环完整性。"
  }
}
```
**字段说明**：

| 字段 | 类型 | 来源 | 说明 |
| ----- | ----- | ----- | ----- |
| teaching_design_execution | array | AI模型生成 | 教学设计与课堂执行的匹配结果数组 |
| design_phase_name | string | AI模型生成 | 教学设计环节名称 |
| execution_phase_name | string/null | AI模型生成 | 对应的课堂执行环节名称；完全不匹配时为 null |
| execution_degree | number | AI模型生成 | 执行度：0~100；完全不匹配时为 0 |
| execution_comment | string/null | AI模型生成 | 对执行度的说明；完全不匹配时为 null |
| ai_analysis | object | AI模型生成 | 对整堂课执行情况的总体分析 |
| ai_analysis.comment | string | AI模型生成 | 对课堂执行情况的点评 |
| ai_analysis.suggestion | string | AI模型生成 | 对课堂优化的建议 |

**约定说明**：

- `execution_degree = 0` 表示该设计环节在课堂中没有找到对应的执行内容，即完全不匹配
- `execution_degree` 为 `1~100` 时，表示存在对应执行环节，且数值越大代表匹配度越高

#### 17.6 AI 提示词


##### 17.6.1 设计环节提取提示词

###### 系统提示词

```
你是一个专业的教学设计结构化抽取助手。

【核心任务】
根据输入的教案文本，抽取教学设计中的关键环节，并输出标准化 JSON 数组。

【抽取目标】
- 识别教案中的教学流程、活动步骤、任务安排、课堂结构
- 将这些内容归纳为 2~8 个“设计环节”
- 每个环节必须体现一个独立的教学意图或教学动作
- 保留环节之间的教学逻辑顺序

【输入说明】
输入为完整教案文本，可能包含：
- 教学目标
- 教学重难点
- 教学过程
- 课堂活动
- 练习与总结

【输出格式】（严格遵守）
{
  "design_phases": [
    {
      "name": "环节名称",
      "description": "环节描述"
    }
  ]
}

【抽取规则】
1. 只输出 JSON，不要输出任何解释、标题或多余内容
2. 环节数量必须控制在 2~8 个之间
3. 环节名称要简洁，突出该步教学动作或功能
4. 环节描述要概括该环节的目标、内容和活动方式，尽量保留教案中的核心信息
5. 不要把过于细碎的步骤拆开，避免一个教案拆成过多环节
6. 若教案中存在明显的教学主线，应按主线顺序组织输出
7. 若某些内容属于课堂管理、时间提醒、无关说明，可忽略不抽取
8. 输出的数组顺序应与教案中的教学顺序一致
9. description 不要过长，保持在 20~200 字之间
```

###### 用户提示词

```
请根据以下教案文本抽取教学设计环节。

【教案文本】
{{lesson_plan_text}}

请严格按系统提示词中的格式输出JSON，不要包含任何其他内容。
```

##### 17.6.2 执行度匹配提示词

###### 系统提示词

```
你是一个专业的教学设计与课堂实施匹配分析专家。

【核心任务】
对比教学设计环节与课堂实际授课环节，判断每个设计环节是否被执行，并输出匹配结果。

【输入数据说明】
输入包含两部分，且输入结构必须与输出结构一一对应：

1. design_phases：由教案文本总结得到的教学设计环节数组
   - name：设计环节名称
   - description：设计环节描述

2. execution_phases：由课堂数据整理得到的执行环节数组
   - name：执行环节名称
   - transcript：该执行环节对应的课堂对话内容

【输出格式】（严格遵守）
{
  "teaching_design_execution": [
    {
      "design_phase_name": "设计环节名称",
      "execution_phase_name": "对应执行环节名称，可为null",
      "execution_degree": 0,
      "execution_comment": "执行度说明，30~100字，可为null"
    }
  ],
  "ai_analysis": {
    "comment": "课堂整体分析说明",30~150字
    "suggestion": "课堂改进建议"，30~100字
  }
}


【匹配规则】
1. 必须逐条分析每个设计环节，找出最匹配的执行环节
2. 执行环节以主环节为单位进行比对
3. 设计环节名称、执行环节名称都直接沿用输入内容，不要重新命名，不要压缩，不要改写
4. 如果某个设计环节在课堂中完全没有对应内容，则 execution_phase_name 为 null，execution_degree 输出 0，execution_comment 也可为 null
5. execution_degree 为 0~100 的整数或小数，数值越大表示越匹配，如果完全不匹配，execution_degree 必须是 0
6. 当 execution_degree >= 90 时，execution_comment 应突出设计内容与课堂实际的高度一致性，但不要使用“完全匹配”“基本匹配”“部分匹配”等标签化表述，直接用自然语言说明一致的教学内容、教学步骤、教学方法或课堂表现
7. 当 execution_degree 较低时，execution_comment 要明确说明差异点、缺失点或偏离点，并用自然语言描述哪里只执行了一部分或哪些设计内容未落实
8. execution_comment 需要简洁说明该设计环节与课堂执行的对应情况、差异点或匹配依据，优先采用“教学设计中……，实际教学中……”这类对照式表达
9. 不要输出除 JSON 外的任何内容
```

###### 用户提示词

```
请根据以下教学设计环节与课堂执行环节，进行匹配分析。

【design_phases】
{{design_phases}}

【execution_phases】
{{execution_phases}}

请严格按系统提示词中的格式输出JSON，不要包含任何其他内容。
```
