## 功能概述

将课堂录音/视频自动转成带角色标注的文字稿，方便后续分析学生学习情况。

---

## 实现步骤

### 步骤1：音频识别（语音转文字）

**做什么**：把用户上传的音视频文件，转换成文字内容。

**用户操作**：

1. 用户上传课堂录音（mp3/wav/m4a）或课堂视频（mp4/avi）
2. 系统自动处理，生成文字稿

**处理流程**：

```
用户上传文件
    ↓
如果是视频 → 用工具提取音频
    ↓
调用火山引擎ASR服务（豆包大模型版）
    ↓
生成原始识别结果（JSON格式）
```

**输出**：原始识别JSON文件，包含所有识别出的文字和时间戳

**模型返回数据结构示例**（节选）：

```json
{
  "text": "已经在的同学打开书，背一下春江花月夜啊，自己。好，上课。…",
  "utterances": [
    {
      "additions": {
        "speaker": "1"
      },
      "start_time": 20890,
      "end_time": 24930,
      "text": "已经在的同学打开书，背一下春江花月夜啊，自己。",
      "words": [
        {
          "text": "已",
          "start_time": 20890,
          "end_time": 21130,
          "confidence": 0
        },
        {
          "text": "经",
          "start_time": 21130,
          "end_time": 21250,
          "confidence": 0
        }
      ]
    },
    {
      "additions": {
        "speaker": "2"
      },
      "start_time": 24930,
      "end_time": 27930,
      "text": "好，上课。",
      "words": []
    }
  ]
}
```

**技术说明**（供开发参考）：

- 视频格式使用 FFmpeg 提取音频
- 使用火山引擎 `volc.bigasr.auc` 服务
- 模型名称：`bigmodel`（大模型版）
- 配置参数：开启标点预测、逆文本归一化、说话人分离

### 步骤2：数据预处理与角色识别

**做什么**：把原始识别结果整理干净，识别角色，保留逐字数据用于后续分析。

**处理流程**：

```
原始识别JSON
    ↓
清理数据（去除additions嵌套）
    ↓
提取包含多个说话人的对话片段
    ↓
调用AI大模型（阿里千问）判断哪个是老师
    ↓
保留逐字数据（words数组）
    ↓
生成带角色标注的完整数据
```

**输出**：处理后JSON文件

**数据结构示例**：

```json
{
  "utterances": [
    {
      "start_ms": 20890,
      "end_ms": 24930,
      "text": "已经在的同学打开书，背一下春江花月夜啊，自己。",
      "role": "teacher",
      "words": [
        {"word": "已", "start_ms": 20890, "end_ms": 21130},
        {"word": "经", "start_ms": 21130, "end_ms": 21250}
      ]
    }
  ],
  "metadata": {
    "total_duration_ms": 2634070,
    "total_utterances": 556,
    "total_words": 7534
  }
}
```

**字段说明**：


| 字段       | 类型     | 说明                              |
| -------- | ------ | ------------------------------- |
| start_ms | int    | 开始时间（毫秒）                        |
| end_ms   | int    | 结束时间（毫秒），时长 = end_ms - start_ms |
| text     | string | 完整句子文本                          |
| role     | string | teacher / student               |
| words    | array  | 逐字数据（用于语速分析）                    |

### 步骤3：教学环节分析

#### 3.1 功能描述

**做什么**：基于课堂文字稿，自动识别并划分教学环节结构，生成 AI 分析评价。

**数据来源**：步骤2输出的 `utterances` 数组（需先提取不含 words 的简化版本）

**处理流程**：

```
utterances数组
    ↓
提取简化版本（去除words，只保留role/text/start_ms/end_ms）
    ↓
调用AI大模型（阿里千问）
    ↓
识别教学环节结构
    ↓
生成带时间戳的环节分析
```

**数据提取示例**（给模型用）：

```javascript
// 从完整数据中提取简化版本
const simplified = utterances.map(u => ({
  role: u.role,
  text: u.text,
  start: u.start_ms,
  end: u.end_ms
}));
```

```javascript
// 毫秒 → 时长显示（4'45''）
function formatDuration(ms) {
```

### 步骤4：课堂结构分析（S-T / Rt-Ch）

#### 4.1 功能描述

**做什么**：基于预处理后的 utterances 数据，计算 S-T 和 Rt-Ch 指标，绘制行为分析图表，并判断课堂类型。

**数据来源**：步骤2输出的 `utterances` 数组

**处理流程**：

```
utterances数组
    ↓
S-T分析（每分钟采样）
    ↓
Rt-Ch分析（每10秒采样）
    ↓
计算指标并判断课堂类型
    ↓
绘制图表 + 生成AI分析
```

---

#### 4.2 S-T 行为分析图

##### 采样规则


| 参数   | 值        | 说明        |
| ---- | -------- | --------- |
| 采样间隔 | 60秒（1分钟） | 每隔1分钟采样一次 |
| 累计计算 | 从0开始     | 逐步累加师生时长  |


##### 计算公式

```
采样点 i (i = 0, 1, 2, ...):
  T累计(i) = sum(教师发言时长)，从0到采样点i
  S累计(i) = sum(学生发言时长)，从0到采样点i

图表坐标点:
  x = T累计(i) / 60000  // 转分钟
  y = S累计(i) / 60000  // 转分钟
```

##### 图表样式

```
Y（学生累计时长，分钟）
  │
20 ┤              ●━━●
  │            /
10 ┤          /
  │        /
 0 ┼──────────────────→ X（教师累计时长，分钟）
 0    5    10   15   20
```

#### 4.3 Rt-Ch 行为分析图

##### 采样规则


| 参数   | 值          | 说明         |
| ---- | ---------- | ---------- |
| 采样间隔 | 30秒        | 每隔30秒采样一次  |
| 采样方式 | 判断该时间点谁在说话 | 取说话时间最长的角色 |


##### 计算公式

```
采样得到序列：[T, T, S, S, S, T, ...]（T=教师，S=学生）

N = 采样总数（发言段数量）
NT = 教师发言段数
Rt = NT / N  // 教师行为占有率

g = 连续行为组数量（如：TT | S | T | SS = 4组）
Ch = (g - 1) / N  // 师生转化率
```

##### 图表样式

```
         Ch (转化率)
            │
         1.0 ┤      ╱对话型
            │     ╱ ╲
         0.6 ┤   ●───●
            │   ╱│   │╲
            │  ╱ │混合│ ╲
         0.4 ┤ ╱  │型  │ ╲
            │╱   │   │   ╲
            └──────────────────→ Rt (占有率)
              0   0.3  0.5  0.7  1.0
              └──┬──┘   └───┬──┘
              练习型       讲授型
```

##### 四种课堂类型


| 课堂类型 | 划分标准 (Rt 与 Ch 的数值范围)      | 课堂特征                            |
| ---- | ------------------------- | ------------------------------- |
| 讲授型  | Rt ≥ 0.7                  | 教师行为占比极高，课堂以教师单向讲授为主，师生互动较少。    |
| 练习型  | Rt ≤ 0.3                  | 教师行为占比很低，课堂时间主要留给学生进行自主练习或活动。   |
| 对话型  | Ch ≥ 0.4                  | 师生行为转换非常频繁，课堂上师生之间有充分的问答与交流互动。  |
| 混合型  | 0.3 < Rt < 0.7 且 Ch < 0.4 | 教师讲授与学生参与的时间分配较为均衡，既有讲解也有适度的互动。 |


##### 图表区域坐标（前端渲染用）


| 类型  | 形状  | 坐标点                                                     | 背景色 |
| --- | --- | ------------------------------------------------------- | --- |
| 练习型 | 三角形 | (0,0) → (0.3,0) → (0.3,0.6)                             | 浅绿色 |
| 混合型 | 正方形 | (0.3,0) → (0.7,0) → (0.7,0.4) → (0.3,0.4)               | 浅灰色 |
| 讲授型 | 三角形 | (0.7,0) → (1,0) → (0.7,0.6)                             | 浅蓝色 |
| 对话型 | 五边形 | (0.3,0.4) → (0.7,0.4) → (0.7,0.6) → (0.5,1) → (0.3,0.6) | 浅橙色 |


##### 判断逻辑

```javascript
function getClassType(Rt, Ch) {
  if (Rt >= 0.7) return '讲授型';
  if (Rt <= 0.3) return '练习型';
  if (Ch >= 0.4) return '对话型';
  return '混合型';
}
```

#### 4.5 AI 分析模板

##### 分析内容

根据师生占比关系，选用对应模板拼接：

**教师主导（教师占比 > 学生占比 + 5%）**

```
本节课教师行为时长（占比{教师占比}%）大于学生行为时长（占比{学生占比}%），表明本节课是以教师主导的课堂，本节课Rt={Rt值}，Ch={Ch值}，整体表现为{课堂类型}。
```

**学生主导（教师占比 < 学生占比 - 5%）**

```
本节课教师行为时长（占比{教师占比}%）小于学生行为时长（占比{学生占比}%），表明本节课是以学生为中心的课堂，本节课Rt={Rt值}，Ch={Ch值}，整体表现为{课堂类型}。
```

**师生均衡（|教师占比 - 学生占比| ≤ 5%）**

```
本节课教师行为时长（占比{教师占比}%）接近学生行为时长（占比{学生占比}%），表明本节课是师生互动均衡的课堂，本节课Rt={Rt值}，Ch={Ch值}，整体表现为{课堂类型}。
```

##### 变量说明


| 变量   | 计算方式                | 示例   |
| ---- | ------------------- | ---- |
| 教师占比 | 教师累计时长 / 总时长 × 100% | 75%  |
| 学生占比 | 学生累计时长 / 总时长 × 100% | 25%  |
| Rt值  | NT / N，保留2位小数       | 0.75 |
| Ch值  | (g-1) / N，保留2位小数    | 0.12 |
| 课堂类型 | 根据判断规则判断            | 讲授型  |

### 步骤5：知识点结构与分析

#### 5.1 功能描述

**做什么**：基于课堂对话记录，结合学科知识树，分析本节课涉及的知识点，生成知识点树结构及每个知识点的详细描述。

**数据来源**：

1. 步骤2输出的 `utterances` 数组（简化版，去掉 words）
2. 用户上传音视频时选择的年级和学科对应的知识树 JSON

**处理流程**：

```
步骤2输出 utterances 数组
    ↓
提取简化版本（去除words，只保留role/text/start_ms/end_ms）
    ↓
根据用户选择的学科和年级，获取对应的知识树
    ↓
调用AI大模型（阿里千问）
    ↓
识别知识点结构 + 每个知识点的描述和时间段
```

---

#### 5.2 AI 提示词

##### 系统提示词

```
你是一个专业的教学分析专家。

【核心任务】
分析课堂对话数据，从知识树中选择本节课涉及的知识点，构建知识点树结构，并记录每个知识点的讲解时间段。

【数据说明】
1. 课堂对话JSON（简化版），每条记录包含：
   - role: "teacher" 或 "student"
   - text: 说话内容
   - start: 开始时间（毫秒）
   - end: 结束时间（毫秒）

2. 学科知识树JSON，树状结构，层级为：学科 → 一级知识域 → 二级知识模块 → 三级知识专题 → 四级知识点。

【核心要求】
1. 知识点定位精准：找到与课堂内容最直接相关的知识树节点作为顶级
2. 子集丰富：挖掘所有与课堂内容相关的知识点，不仅限于直接提到的
3. 包含所有层级：knowledgeTree 中的每个节点都需要在 knowledgePoints 中有对应条目
4. 记录时间段：每个知识点记录课堂中讲解该知识点的起始和结束时间（毫秒）
5. 时间段可重合：不同知识点的时间段没有互斥限制，可能在同一时段讲解多个知识点

【时间戳记录规则】
1. start_ms：该知识点在课堂中首次讲解的起始时间（毫秒）
2. end_ms：该知识点在课堂中讲解的结束时间（毫秒）
3. 各节点时间独立：父子节点的时间段各自独立记录，不做强制关联

【输出格式】（严格遵守）
{
  "knowledgeTree": {
    "label": "知识点名称",
    "children": [
      { "label": "子知识点", "children": [...] }
```

### 步骤6：教师语速分析

#### 6.1 功能描述

**做什么**：基于预处理后的 utterances 数据，计算教师的总字数、授课时长、平均语速，并绘制每分钟的语速折线图。

**数据来源**：步骤2输出的 `utterances` 数组

**处理流程**：

```
utterances数组
    ↓
过滤出所有 role="teacher" 的记录
    ↓
计算总字数、授课时长、平均语速
    ↓
每分钟采样，计算每分钟语速
    ↓
绘制语速折线图 + 生成AI分析
```

---

#### 6.2 计算规则

##### 数据计算


| 指标   | 计算方式                                                              |
| ---- | ----------------------------------------------------------------- |
| 总字数  | 所有 teacher 发言的 text 字符数之和                                         |
| 讲授时长 | 所有 teacher 发言段的时长之和 = sum(teacher.end_ms - teacher.start_ms)，转为分钟 |
| 平均语速 | 总字数 / 讲授时长（字/分钟），保留整数                                             |


##### 语速折线图采样


| 参数   | 值        | 说明                  |
| ---- | -------- | ------------------- |
| 采样间隔 | 1分钟      | 每隔1分钟采样一次           |
| X轴   | 时间（分钟）   | 0', 1', 2', ..., N' |
| Y轴   | 语速（字/分钟） | 该分钟内的教师说话字数         |


##### 采样计算方式

```
第 n 分钟的语速：
  - 时间范围：(n-1)*60000 毫秒 ~ n*60000 毫秒
  - 该范围内所有 teacher 发言的字数之和
  - 如果该分钟没有老师发言，语速为0
```

### 步骤7：高频词汇分析

#### 7.1 功能描述

**做什么**：从教师讲授文本中抽取出现频率最高的 Top50 词汇，生成词云数据；并基于高频词结果调用 AI 模型生成点评与建议。

**后端技术栈**：Go

**前端技术栈**：Flutter

**处理流程**：

```

    ↓
过滤 role="teacher" 的文本并合并
    ↓
中文分词 + 清洗过滤（停用词/长度/标点等）
    ↓
词频统计并排序
    ↓
取Top50生成词云数据（后端计算）
    ↓
将Top50词频作为参数嵌入提示词，调用AI大模型
    ↓
返回：词云数据 + AI点评/建议
```

#### 7.2 后端计算规则（词频统计）

##### 建议技术方案（Go）

- **中文分词**：建议使用 `gojieba`（jieba 的 Go 封装）进行分词。
- **停用词表**：建议使用“哈工大停用词表（HIT stopwords）”作为通用基础，并叠加课堂场景的自定义停用词进行迭代。
  - 参考链接：
    - [https://github.com/goto456/stopwords/blob/master/hit_stopwords.txt](https://github.com/goto456/stopwords/blob/master/hit_stopwords.txt)

##### 统计范围

- 仅统计：`utterances` 中 `role = "teacher"` 的 `text`
- 统计单位：词（token）

##### 分词与清洗规则

后端对教师文本进行中文分词后，按以下规则过滤：

1. **停用词过滤**：过滤常见虚词、口头禅、称呼词。停用词表应支持配置和迭代。
2. **长度过滤**：默认过滤长度为1的词，避免信息量过低。
3. **字符类型过滤**：过滤纯标点、纯空白、无意义符号；纯数字可默认过滤。
4. **归一化**（可选）：统一全角/半角、大小写等。

##### 词频统计与排序

- 词频 `count`：某词在 teacher 文本中出现次数（按分词 token 计数）
- 取 Top50：按 `count` 从高到低排序，取前50个词

### 步骤8：师生时长占比分析

#### 8.1 功能描述

**做什么**：统计课堂中教师与学生的说话时长，并从两个维度进行展示：

1. 全课堂维度：教师/学生说话时长占比（饼图）
2. 教学环节维度：各主教学环节内教师/学生说话时长（堆叠柱状图）

并基于统计数据调用 AI 模型生成“评价 + 建议”。

**数据来源**：

- `utterances`：步骤2输出的师生分角色语音转写结果（含 start_ms/end_ms/role）
- `teaching_phases`：步骤3输出的教学环节（含各主环节的起止时间段）

**处理流程**：

```
utterances + teaching_phases
    ↓
计算全课堂 teacher/student 总说话时长
    ↓
按主教学环节统计 teacher/student 说话时长
    ↓
生成：饼图数据 + 堆叠柱数据
    ↓
将统计结果作为参数嵌入提示词，调用AI大模型
    ↓
返回：图表数据 + AI评价与建议
```

---

#### 8.2 计算规则

##### 8.2.1 全课堂师生说话时长

- 过滤条件：仅统计 `role ∈ {teacher, student}` 的 utterances
- 单句时长：`duration_ms = end_ms - start_ms`
  - 若 `duration_ms <= 0` 视为异常数据，忽略
- 统计：
  - `teacher_total_ms = sum(duration_ms where role=teacher)`
  - `student_total_ms = sum(duration_ms where role=student)`
- 占比计算（饼图）：
  - 分母：`speaking_total_ms = teacher_total_ms + student_total_ms`
  - `teacher_ratio = teacher_total_ms / speaking_total_ms`
  - `student_ratio = student_total_ms / speaking_total_ms`

说明：占比的分母使用“师生说话总时长”，不包含课堂中无人说话的空档时段。

##### 8.2.2 各主教学环节内师生说话时长

- 统计粒度：使用 `teaching_phases` 中的**主环节**作为柱状图粒度
- 环节时间段：每个主环节具有起始/结束时间点
- 统计口径：
  - 对于每个主环节区间内的 utterances，分别累加 teacher/student 的 `duration_ms`
  - 生成该环节：`teacher_ms`、`student_ms`
- 环节内占比（用于 tooltip 展示）：
  - 分母：`phase_speaking_ms = teacher_ms + student_ms`
  - `teacher_ratio = teacher_ms / phase_speaking_ms`
  - `student_ratio = student_ms / phase_speaking_ms`

说明：环节内占比的分母同样使用“该环节内师生说话总时长”，不包含该环节内的沉默/过渡空档。


### 步骤9：问答评数据抽取（公共前置）

#### 9.1 功能描述

**做什么**：基于预处理后的 `utterances` 对话数据，提取课堂中的多轮“问-答-评”结构化数据（数组）。

- **问（q）**：教师提问（必有且仅1句）
- **答（a）**：学生针对该提问的关键回答（最多1句，可为空）
- **评（f）**：教师针对学生回答的关键反馈（最多1句，可为空）

说明：课堂中存在多轮问答，因此输出为数组 `qa_list[]`。该数据是后续“问题分类 / 问题链分析 / 回答分类 / 思维分析 / 教师反馈分析”等板块的公共输入。

**处理流程**：

```
utterances数组
    ↓

    ↓
匹配其对应的学生关键回答（a，可为空）
    ↓
匹配其对应的教师关键反馈（f，可为空）
    ↓
输出 qa_list[]（一问一答一评，均最多1句）
```

### 步骤10：问题分类（教师提问分析）

#### 10.1 功能描述

**做什么**：基于步骤9输出的 `qa_list`，对教师提问进行分类打标签，并形成图表与 AI 分析内容。

本板块包含：

1. 问题类型分布（4MAT）图表
2. 认知层次分布（布鲁姆）图表
3. 开放/封闭问题分布图表
4. AI 分析文本块（点评 + 建议）
5. 问答评详情列表（用于查看每条问答评的标签与内容）

**数据来源**：步骤9输出的 `qa_list`

**处理流程**：

```
qa_list
  ↓
对每条 q（教师提问）打标签（4MAT + Bloom + 开放/封闭）
对每条 f（教师反馈）打标签（反馈类型；用于详情展示与后续教师反馈分析复用）
  ↓
统计分布并生成图表数据
  ↓
调用AI模型生成点评 + 建议
```

---

#### 10.2 标签体系

##### 10.2.1 4MAT 问题类型（单选）

- 为何（why）：激发价值认同/动机，强调“为什么学、有什么意义”
- 是何（what）：获取概念/事实/定义，强调“是什么”
- 如何（how）：聚焦方法/步骤/操作，强调“怎么做”
- 若何（what_if）：迁移与创新，强调“如果…会怎样/还能怎么用/是否可变通”

##### 10.2.2 布鲁姆问题类型（单选）

- 记忆（remember）：回忆、识别、复述
- 理解（understand）：解释、举例、归纳、概括
- 应用（apply）：在情境中运用方法/规则
- 分析（analyze）：比较、拆分、找关系、推断原因
- 评价（evaluate）：判断优劣、给出理由、基于标准评估
- 创造（create）：提出新方案、设计新情境、重组创新

##### 10.2.3 开放/封闭（单选）

- 开放性：允许多种答案/多角度表达/需要阐述理由或过程
- 封闭性：答案唯一或范围极小（如“对/错”“能/不能”“是多少”）

##### 10.2.4 教师反馈类型（单选，仅用于打标与复用）

- 评价性：对学生回答进行判断/评价（对错、好不好、是否到位）
- 指导性：给出纠错、提示、引导步骤或补充解释
- 鼓励性：鼓励、肯定情绪支持（很好、继续、你很棒等）
- none：无反馈（f 为空时）

### 步骤11：问题链分析（教师提问分析）

#### 11.1 功能描述

**做什么**：基于步骤9输出的 `qa_list` 中所有教师提问，识别本节课有意义的问题，按照教师提问顺序和问题内涵，提炼课堂“问题链”，还原教师提问的逻辑链路，并对每个问题链节点进行定性分析。

本板块包含：

1. 问题链节点列表
2. 每个节点的核心问题
3. 每个节点关联的原始教师问题集
4. 每个节点的学科思维体现
5. 每个节点的问题情境类型
6. 每个节点的问题集类型
7. 问题链整体 AI 分析文本块（点评 + 建议）

**数据来源**：步骤9输出的 `qa_list`，主要使用其中的教师提问字段 `qa_list[].q`，并保留 `start_ms` 用于页面定位。

**处理流程**：

```
qa_list
  ↓
提取所有教师问题 q（按 start_ms 时间顺序）
  ↓
调用AI模型识别有意义的问题
  ↓
按提问顺序和问题内涵聚合为若干问题链节点
  ↓
为每个节点命名，并识别核心问题与关联问题集
  ↓
判断每个节点的学科思维、问题情境、问题集类型
  ↓
调用AI模型生成问题链整体点评 + 建议
```

---

#### 11.2 分析维度说明

##### 11.2.1 问题链节点

问题链节点是对一组具有共同教学意图或逻辑关联的教师问题的概括。一个节点通常对应课堂推进中的一个关键思考环节，例如：意象分析、情感体验、哲理探讨、方法归纳、结构分析等。

每个节点需要包含：

- 节点序号：按课堂提问推进顺序排列
- 节点名称：对该组问题的高度概括
- 核心问题：从该节点关联问题集中选出的最能代表该节点教学意图的问题
- 关联问题集：属于该节点的全部原始教师问题

##### 11.2.2 学科思维体现

学科思维用于描述该问题链节点主要引导学生运用的学科思考方式。学科思维类型需要根据课程学科选择，不同学科使用不同枚举。

- **语文**：形象思维 | 逻辑思维 | 辩证思维 | 创造思维 | 元认知思维 | 系统思维
- **数学**：抽象思维 | 计算思维 | 应用思维 | 建模思维 | 推理思维 | 数据分析思维 | 批判性思维 | 元认知思维 | 创新思维
- **英语**：辨识思维 | 推理思维 | 批判性思维 | 迁移思维

每个节点需要输出：

- `type`：学科思维类型
- `comment`：简要说明该节点如何体现该类学科思维

##### 11.2.3 问题情境类型

问题情境用于判断该节点下的问题是否依托具体情境，以及情境复杂程度。

枚举值：

- 无情境：问题集不涉及具体问题情境，主要是概念、事实、记忆或直接判断
- 简单情境：问题集中包含简单的问题情境，学生可基于单一材料或局部文本作答
- 复杂情境：问题集中包含较复杂的问题情境，需要学生综合多个信息、多个意象、多个关系或多个层次进行理解

每个节点需要输出：

- `type`：无情境 | 简单情境 | 复杂情境
- `comment`：简要说明判断依据

##### 11.2.4 问题集类型

问题集类型用于描述同一节点内一组问题的组织方式和推进逻辑。

枚举值：

- 平行型：围绕同一内容提出一系列同类型、并列关系的问题
- 收敛型：由开放性问题开始，后续问题逐步缩小范围，聚焦到课程内容或关键结论
- 拓展型：先提出与主题最直接相关的问题，再逐步过渡到开放性、迁移性或延展性问题
- 提高型：从简单问题开始，后续问题难度逐步增加，推动学生深入思考
- 下降型：先提出较难或综合性问题，再逐步降低难度，帮助学生分解理解

每个节点需要输出：

- `type`：平行型 | 收敛型 | 拓展型 | 提高型 | 下降型
- `comment`：简要说明该节点问题推进逻辑

### 步骤12：思维分析（学生回答分析）

#### 12.1 功能描述

**做什么**：基于步骤9输出的 `qa_list`，聚焦学生回答质量与思维表现。系统提取每条“问-答”对（仅使用 `q` 与 `a`，不含任何标签字段），结合课程学科 `subject`，调用 AI 模型判断学生回答对应该学科各项思维的体现水平，并生成整体点评与建议。

本板块包含：

1. 各思维维度体现情况数组（逐维度输出：思维名称 + 体现情况 + 点评）
2. 思维分析整体 AI 分析文本块（点评 + 建议）

**数据来源**：步骤9输出的 `qa_list`（仅使用 `q` 与 `a` 字段；`a == null` 的条目允许存在，模型能处理）。

---

#### 12.2 学科与思维维度

本步骤必须接收课程学科 `subject`，不同学科使用不同思维维度枚举。

- `subject` 取值：语文 | 数学 | 英语
- **语文思维维度**：形象思维 | 逻辑思维 | 辩证思维 | 创造思维 | 元认知思维 | 系统思维

- **英语思维维度**：辨识思维 | 推理思维 | 批判性思维 | 迁移思维

---

#### 12.3 输出数据结构

说明：本步骤的输出以 `studentAnswerThinking` 为模块名，包含：

- `thinking_dimensions`：各思维维度体现情况数组

**JSON 结构示例**：

### 步骤17：教学环节执行度

#### 17.1 功能描述

**做什么**：基于教学设计（教案）与课堂授课过程，对比每个“设计环节”和“执行环节”的匹配情况，输出教学环节执行度分析结果。

本功能用于回答两个问题：

1. 教学设计中的环节，在课堂中是否被实际执行到
2. 如果执行到了，执行得有多接近设计目标，即执行度是多少

系统会将教学设计总结为结构化的“设计环节”数组，再将课堂实际授课过程整理为结构化的“执行环节”数组，最后通过模型逐条比对，输出每个设计环节对应的执行结果。

**数据来源**：

1. 步骤16中教案处理流程输出的教案文本
2. 步骤2输出的 `utterances` 数组（课堂师生对话数据，含时间戳）
3. 步骤3输出的 `teaching_phases` 数组（含主环节、子环节及时间戳）

**处理流程**：

```
教案文本（步骤16输出）
    ↓
调用AI大模型总结教学设计环节
    ↓
生成设计环节数组（2~8个环节）
    ↓
步骤2输出 utterances 数组 + 步骤3输出 teaching_phases 数组
    ↓
程序按主环节聚合子环节时间，提取每个主环节对应的课堂对话
    ↓
生成执行环节数组（主环节 + 对话内容）
    ↓
调用AI大模型比对设计环节与执行环节
    ↓
输出每个设计环节的执行度、匹配执行环节、说明
```

#### 17.2 设计环节生成规则

教案文本需要先经过模型总结，抽取出教学设计中的关键环节，形成标准化数组，供后续执行度比对使用。

**输入数据**：步骤16输出的教案文本

**输出要求**：

- 设计环节数量：2~8个
- 每个环节必须包含：
  - 环节名称
  - 环节描述
- 环节名称应概括教学设计中的一个核心步骤或教学任务
- 环节描述应保留该环节的教学目标、组织方式、教学内容或活动特征，便于后续与课堂实际执行内容比对
- 若教案内容较长，允许模型进行归纳总结，但不得遗漏关键教学逻辑

**处理流程**：

```
教案文本
    ↓
调用AI大模型总结
    ↓
输出设计环节数组
```

**JSON 结构示例**：

```json
{
  "design_phases": [
    {
      "name": "导入新课",
      "description": "教师通过问题引导或情境创设激发学生兴趣，引入本节课的学习主题。"
    },
    {
      "name": "新知讲解",
      "description": "围绕核心知识点进行讲解，结合案例、板书或演示帮助学生理解课堂重点。"
```

#### 17.3 执行环节生成规则

课堂授课过程的数据来自步骤2和步骤3。

步骤3已经识别出主环节和子环节，因此程序先按主环节进行聚合，再把该主环节范围内的课堂对话提取出来，形成执行环节数据。

**处理方式**：

1. 读取步骤3输出的 `teaching_phases`
2. 对每个主环节，取其下所有子环节中：
   - 第一个子环节的 `start_ms` 作为主环节起始时间
   - 最后一个子环节的 `end_ms` 作为主环节结束时间
3. 使用该时间区间去筛选步骤2输出的 `utterances`
4. 获取该主环节内的课堂对话内容，形成执行环节数组

**执行环节数组结构**：

- 主环节名称
- 主环节下的课堂对话内容

#### 17.4 AI 比对规则

系统会把“设计环节数组”和“执行环节数组”同时输入模型，由模型逐条判断匹配关系。

**比对目标**：

- 一个设计环节对应课堂中最相近的一个执行环节
- 如果课堂中没有与该设计环节相匹配的执行内容，则该设计环节可判定为未执行
- 如果匹配不完整，则输出部分匹配，并给出执行度百分比

**执行度定义**：

- 执行度表示“课堂实际执行内容”与“教学设计环节”在语义与行为层面的贴合程度
- 执行度范围为 0~100
- 执行度越高，说明课堂实际开展内容越接近教案设计
- 若完全不匹配，则该设计环节对应的执行环节可为 `0`，且执行度与说明不输出

**执行度标签规则**：

- `>= 90%`：完全匹配
- `< 90%`&`>0`：部分匹配

说明：执行度标签由前端根据执行度数值映射生成，不需要模型直接返回标签。

### 步骤18：生成性教学内容

#### 18.1 功能描述

**做什么**：基于教案文本和课堂对话内容，识别并提取课堂中由教师即兴发挥、临时拓展或超出教案预设的生成性教学内容，按课堂主环节归类呈现，并给出整体分析点评。

本功能用于回答以下问题：

1. 课堂中哪些内容是教师在教案之外临时生成、发挥或拓展的
2. 这些生成性内容分布在哪些教学环节，各自有什么特点
3. 整体来看，生成性内容的占比和质量如何，有哪些值得肯定或需要改进的地方

**生成性内容的定义**：相对于教案中预设的教学内容而言，课堂中教师临时引出的内容，包括即时补充的典故/例子、生活化类比、跨文本关联、追问延伸、情感升华引导、课堂管理中的即兴互动等。

**数据来源**：

1. 步骤16中教案处理流程输出的教案文本
2. 步骤17.3执行环节生成规则输出的执行环节数组（含主环节名称及对应的课堂对话内容）

**处理流程**：

```
教案文本（步骤16输出）+ 执行环节数组（步骤17.3输出，含主环节 + 对话内容）
    ↓
程序将教案文本与执行环节数组同时传给模型（一次调用）
    ↓
模型按主环节逐个分析，对照教案提取课堂中教案未涉及的内容
    ↓
输出每个主环节下的生成性内容数组 + 整体分析点评
```

#### 18.2 AI 识别规则

系统将教案文本和执行环节数组同时输入模型，由模型基于对话内容逐环节分析，识别出教案预设之外教师生成的临场内容。

**识别目标**：

- 识别教案文本中未涵盖、但在课堂对话中实际出现的内容
- 识别不属于该环节预设教学内容，但教师主动引出的延伸、拓展或追问
- 不识别教案中已有、仅由教师重复或照本宣科的内容

**识别原则**：

1. 以课堂主环节为单位逐个分析，不遗漏任一主环节
2. 生成性内容的标题应简洁概括该内容的核心特征，4~10字
3. 生成性内容的描述应说明"教案中是否有/是否有提及"以及"课堂上具体发生了什么"，10~100字
4. 若某主环节下没有生成性内容，则该环节对应数组为空，不输出占位
5. 生成性内容的描述优先采用"教案中未提及/教案中无相关内容，课堂上教师……"的表达方式
